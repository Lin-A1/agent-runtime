## 实现三个功能：回退（原位截断）、`/`与`@`主动工具集、插话/提问队列

### 背景与现状（已探明）
- **回退**：目前只有 `POST /v1/session/:id/fork{atSeq?}`（append-only 分支到新会话）。`EventStore` 只有整条 `delete`，无按 seq 截断。`Session.replay` 不支持截断。用户选择 **原位截断当前会话**。
- **`/` 与 `@`**：Composer 补全只插入文本 token（`chooseCompletion`→`replaceCompletion`）。`POST /v1/session/:id/command` 已能执行命令返回展开文本（`app.runCommand`），但 Composer 发送时从不调用它；`@agent/@skill/@mcp` 引用在后端**无任何消费者**，是纯文本约定。用户选择 **真正触发动作**。
- **#6 插话/提问**：busy 会话 `send` 已自动转 `steer`（文本注入）→ 插话能力已具备；`ApprovalDock` 已实现 question 队列 + 翻页 + 超时。缺的是：明确的插话 UI 提示、提问队列按 session 分组显示来源。

### 实现方案

#### A. 回退功能（原位截断当前会话）
**core（packages/core）**
1. `session/store.ts`：`EventStore` 接口新增 `truncate(aggregate_id: string, atSeq: number): Promise<void>`；`MemoryEventStore` 用 `#events.get(id)?.splice(atSeq+1)`。
2. `session/sqlite.ts`：`truncate` 用 `DELETE FROM event WHERE aggregate_id=? AND seq>?`，并把 `event_sequence` 的 seq 回退到 `atSeq`（防止后续 append 复用旧 seq 冲突——用 `#nextSeq` 的 ON CONFLICT 逻辑，把 seq 直接 UPDATE 为 atSeq）。
3. `schema/event.ts`：`SessionEvent` 新增 `Session.Truncated { sessionId; atSeq; by: "host" | "model"; ts }`。

**runtime（packages/runtime）**
4. `app.ts`：`App` 接口新增 `truncate(atSeq: number): Promise<void>`。实现：`await events.truncate(sessionId, atSeq)` + `await events.append(sessionId, "Session.Truncated", { sessionId, atSeq, by: "host", ts: Date.now() })`。若 atSeq <0 或 > latestSeq 则不截断并抛类型错误。

**server（packages/server）**
5. `server.ts`：新增 `POST /v1/session/:id/truncate {atSeq}`（放在 fork 路由附近，line ~1153）。解析 body、校验 `atSeq`，调用 `found.app.truncate(atSeq)`，返回 `{ truncated: true, atSeq }`；atSeq 非法返回 400；remote 返回 501。

**web（apps/web）**
6. `api/client.ts`：新增 `truncateSession(id, atSeq)`。
7. `api/types.ts`：无新类型（`Session.Truncated` 走 `StoredEventRow` 通用）。需在 `fold.ts` 的 foldTranscript 遇到 `Session.Truncated` 时**截断已累积的 items**（回退后重放）。
8. `components/Transcript.tsx`：UserTurnView 加"回退到此"按钮（`onRewind`），调用 `truncateSession(sessionId, turn.seq)` 后重新 load 该 session。需把 `onRewind` 传入 UserTurnView。回退确认：用 `window.confirm` 提示会删除该 turn 及其后续。

#### B. `/` 与 `@` 主动工具集（真正触发动作）
**server（packages/server）**
9. `server.ts`：新增 `POST /v1/session/:id/references/resolve {text}`：解析 `@agent:name`、`@skill:name`、`@mcp:server/uri`，返回 `{ expanded: string, resolved: Array<{ kind, label, content }> }`。
   - `@agent:name` → `plugins.get("agent", name)`，注入 `[agent: name]\n<body?>`。
   - `@skill:name` → `discoverSkills(pluginsDir)` 查 name，注入 `[skill: name]\n<body|description?>`。
   - `@mcp:server/uri` → `mcpResources.readResource(server, uri)`，注入 `[mcp: server/uri]\n<text>`。
   - 用 `app` 的 `pluginRegistry`/`pluginsDir`/`mcpResources`（需确认 server 侧能访问这些——`pluginsDir` 在 server 有，`mcpResources` 在 config 有）。

**web（apps/web）**
10. `api/client.ts`：新增 `resolveReferences(id, text)`。
11. `components/Composer.tsx`：
    - `doSend` 中，若文本单行以 `/` 开头 → 调 `api.runCommand(sessionId, text)` 得 `{output}`，把 output 字符串作为发送内容（append 原文注释）。
    - 若文本含 `@` 引用 → 调 `resolveReferences`，把 `expanded`（原文本+注入内容）作为发送内容传给 `send`。
    - 两个处理都失败时回退到原文本发送（不阻断）。

#### C. 插话 / 提问队列
**web（apps/web）**
12. `components/Composer.tsx`：busy 时 placeholder 已显示"继续告诉 agent 下一步…"，改为更明确的插话语义（保留）；toolbar 在 busy 时加一个"插话"徽标/提示。
13. `components/ApprovalDock.tsx`：`requestScope` 增强——把 `session ${id.slice(0,8)}` 显示为可读的 session 来源，并在多 question 时按 sessionId 分组显示"来源 A（2）／来源 B（1）"提示。`ApprovalRequest.sessionId` 已有（types.ts:142）。

### 测试与验证
- core：新增 `truncate` 的 memory/sqlite 单测（截断后 read 只到 atSeq，`latestSeq` 正确，append 不复用旧 seq）。
- server：新增 `POST /v1/session/:id/truncate` 测试（200/400/404）、`references/resolve` 测试（agent/skill/mcp 解析）。
- web：新增 `foldTranscript` 遇 `Session.Truncated` 截断 items 的测试；Composer `/`/`@` 发送路径测试（mock api）。
- 全包 `bun typecheck` + `bun test` + web build 回归。

### 边界说明
- 回退是**破坏性**操作（永久删除后续历史），UI 加确认。
- `@mcp` 引用解析依赖 server 配置了 `mcpResources`；`@agent`/`@skill` 依赖 `pluginsDir`。未配置时解析返回未解析原样保留。
- `/` 命令若 `runCommand` 返回 undefined（非命令）则按普通文本发送。
